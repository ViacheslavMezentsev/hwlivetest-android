# Эвристики кнопки «ПУСК»

Задача: при подключённом ST-Link и опознанном MCU за 1–2 секунды ответить, жив ли
микроконтроллер, тактируется ли он, выполняет ли код, остановлен ли, есть ли прошивка
и не стёрта ли Flash. Всё делается **только чтением**: ядро не останавливается, регистры
не меняются. Код — модуль `diag` (`Diagnostics.kt`, `Stm32Clocks.kt`).

Единственный побочный эффект — чтение DHCSR сбрасывает его «липкие» флаги
`S_RETIRE_ST` и `S_RESET_ST`. Они нужны только отладчику, прошивка их не видит.

## Общие проверки Cortex-M

| Раздел | Что читается | Вывод |
|---|---|---|
| Связь | версия адаптера, напряжение цели, DP IDCODE, CPUID | MCU отвечает по SWD; мало напряжения — плата не запитана |
| Ядро | DHCSR 8 раз через 15 мс | `S_RETIRE_ST` — выполняет код; `S_SLEEP` — спит (WFI); `S_HALT` — остановлено; `S_LOCKUP` — заблокировано; `S_RESET_ST` в нескольких выборках — цикл сброса (watchdog, BOR, сбой в начале прошивки) |
| Исключения и сбои | ICSR.VECTACTIVE 5 раз; CFSR, HFSR, MMFAR, BFAR | всё время 2…6 — зависание в обработчике сбоя; ненулевые CFSR/HFSR — сбои были (флаги липкие) |
| Где выполняется код | DEMCR.TRCENA, DWT_PCSR 12 раз | PC в Flash — работает прошивка; в системной памяти — загрузчик ST (BOOT0 = 1); в SRAM — код из ОЗУ; PC не меняется — цикл ожидания или WFI. Без TRCENA выборка PC недоступна (включение — запись) |
| Прошивка | слова 0 и 1 Flash, адрес 0, системная память, VTOR | `0xFFFFFFFF` — Flash стёрта; SP в SRAM и нечётный Reset в Flash — таблица векторов на месте; адрес 0 = Flash или системная память — источник загрузки; VTOR ≠ 0x08000000 — загрузчик + приложение |
| Тактирование | SysTick CSR, RVR, CVR дважды | идёт ли SysTick; при тике 1 кГц HCLK ≈ (RVR + 1) × 1000 |

У Cortex-M0/M0+ нет CFSR/HFSR, VTOR (у M0) и DWT_PCSR — эти пункты пропускаются.

## Профиль устройства

Для известного STM32 профиль выбирается по справочнику DEV_ID. Остальные Cortex-M
получают общую диагностику ядра: без адреса Flash 0x08000000, загрузчика ST, RCC и RDP.
Чтение сигналов по addresses.json остаётся доступным; границы памяти не подтверждены,
каждое указанное слово читается отдельно. SysTick показывает движение и источник,
но без семейства не предполагает делитель HCLK/8 и период тика 1 мс.

На странице «Устройство» можно вручную применить общий Cortex-M либо совместимый
STM32F1/F4/G4-профиль. Это явное предположение пользователя о карте регистров. Профиль
сбрасывается при отключении и не открывает прошивку неизвестного устройства.

Проверка начала Flash не измеряет заполненность всей памяти.

## STM32F1

| Что | Регистр | Разбор |
|---|---|---|
| Защита чтения | `FLASH_OBR` 0x4002201C | бит 1 RDPRT; бит 2 WDG_SW = 0 — IWDG стартует аппаратно |
| Источник SYSCLK | `RCC_CFGR` 0x40021004 | SWS[3:2]: HSI, HSE, PLL; PLLSRC, PLLXTPRE, PLLMUL (×2…×16), HPRE |
| Готовность | `RCC_CR` 0x40021000 | HSEON без HSERDY — кварц не запустился; PLLON без PLLRDY |
| Системная память | 0x1FFFF000 | для определения BOOT0 |

HSI = 8 МГц, PLL от HSI идёт через деление на 2. У connectivity line (F105/F107) есть
PREDIV1 — пока не учитывается.

## STM32F4

| Что | Регистр | Разбор |
|---|---|---|
| Защита чтения | `FLASH_OPTCR` 0x40023C14 | RDP[15:8]: 0xAA — уровень 0, 0xCC — 2, иначе 1; бит 5 WDG_SW |
| Источник SYSCLK | `RCC_CFGR` 0x40023808 | SWS[3:2], HPRE |
| PLL | `RCC_PLLCFGR` 0x40023804 | SYSCLK = вход / M × N / P, вход — HSI 16 МГц или HSE (бит 22) |
| Системная память | 0x1FFF0000 | BOOT0 |

## STM32G4

| Что | Регистр | Разбор |
|---|---|---|
| Защита чтения | `FLASH_OPTR` 0x40022020 | RDP[7:0] как у F4; бит 16 IWDG_SW |
| Источник SYSCLK | `RCC_CFGR` 0x40021008 | SWS[3:2]: 1 HSI16, 2 HSE, 3 PLL |
| PLL | `RCC_PLLCFGR` 0x4002100C | PLLSRC[1:0], SYSCLK = вход / (M+1) × N / R, R = 2, 4, 6, 8 |
| Готовность | `RCC_CR` 0x40021000 | HSION — бит 8, HSIRDY — бит 10 |

## Частота HSE

Из регистров её не узнать. Если SYSCLK зависит от HSE, приложение берёт оценку HCLK по
SysTick (HAL по умолчанию тикает 1 кГц) и пересчитывает в HSE, округляя к частотам
распространённых кварцев (8, 12, 16, 24, 25 МГц и т. п., ±3 %). Если SysTick выключен
или тикает не 1 кГц, частота HSE остаётся неизвестной.

## Отладка во сне

`DBGMCU_CR` 0xE0042004 показывает, держит ли MCU отладочный доступ в SLEEP/STOP/STANDBY.
Если нет, во время сна ядра чтения отвечают WAIT — приложение повторяет запрос
(5 раз, 1–16 мс).

## Инструменты после «ПУСК»

По образцу [stm32-flasher](https://github.com/ViacheslavMezentsev/stm32-flasher):

| Команда stm32-flasher | В приложении | Статус |
|---|---|---|
| `info` | «ПУСК» и экран эксперта | есть |
| `backup` | «Резервная копия Flash»: Intel HEX без хвоста 0xFF, SHA-256 | есть, только чтение |
| `check` | «Сверить с HEX»: сравнение диапазонов HEX с памятью | есть, только чтение |
| `halt` / `go` / `reset` | — | нужна запись в DHCSR/AIRCR, после согласования |
| `erase` / `flash` | — | нужна запись во Flash, после согласования |

Резервная копия читает Flash блоками по 1 КБ, пока ядро работает. При включённом RDP
чтение Flash отладчиком запрещено — инструмент сообщит об ошибке.
