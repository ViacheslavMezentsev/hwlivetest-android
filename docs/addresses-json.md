# Формат addresses.json

Документ описывает текущую реализацию HW Live Test 0.3.13.
[Практический пример и открытие файла](../README.md#пример-addressesjson).

## Назначение

Файл связывает имена сигналов (топики) с адресами памяти и способом декодирования.
Приложение читает значения через ST-Link; ROS на микроконтроллере не требуется.
Полные имена топиков сохраняются в MCAP, короткое имя в списке — последний сегмент пути.

Адреса и типы должны соответствовать конкретной сборке прошивки. Приложение не вычисляет
выражения C/C++ и не разрешает символы ELF при загрузке этого JSON.

## Корневой объект

Нужен JSON-объект с массивом `fields`. Комментарии и завершающие запятые не используйте.
Без объекта или массива `fields` загрузка завершается ошибкой.

Генераторы могут добавлять `schema`, `elf`, `elf_sha256`, `svd`, `firmware`,
`firmware_sha256` и `note`. Текущий загрузчик таблицы читает только `fields`: метаданные
не проверяют соответствие подключённой прошивке и не открывают указанные файлы.
В частности, `schema: 2` не включает отдельный режим разбора.

## Поля сигнала

Каждый элемент `fields` — объект. Задайте непустой `topic`, адрес и явный `kind`.

| Ключ | Тип | Значение |
| :--- | :--- | :--- |
| `topic` | Строка | Уникальное имя, например `/diag/sensor/battery_v` |
| `address_hex` | Строка | Шестнадцатеричный адрес слова, например `0x20001000` |
| `address` | Целое число | Десятичный адрес; имеет приоритет над `address_hex` |
| `kind` | Строка | Способ декодирования из таблицы ниже |
| `message` | Строка | Тип ROS 1 для MCAP; рекомендуется согласовать с `kind` |
| `expr` | Строка | Необязательная подпись C/C++ для отладочных сведений |
| `min`, `max` | Числа | Необязательные включительные границы допустимого значения |
| `mask` | Целое число | Битовая маска в десятичной записи |
| `shift` | Целое число | Сдвиг вправо после маски; используйте 0–31 |
| `source_type` | Строка | Исходный тип для отображения; запасной ключ — `description` |
| `source_file` | Строка | Имя исходного файла для сведений и группировки |
| `size_bits` | Целое число | Для `int32`: 8 или 16 включает расширение знака соответствующей ширины |

Достаточно одного способа записи адреса. Если заданы оба, они должны обозначать одно
место в памяти. Допустимый адрес слова — от `0x00000000` до `0xFFFFFFFC`, кратный 4.

| `kind` | Декодирование 32-битного слова | Обычный `message` |
| :--- | :--- | :--- |
| `float32` | Биты числа IEEE 754, а не перевод целого в вещественное | `std_msgs/Float32` |
| `uint32` | Беззнаковое целое | `std_msgs/UInt32` |
| `int32` | Знаковое целое | `std_msgs/Int32` |
| `uint32_seconds` | Беззнаковое число секунд с отображением времени | `std_msgs/UInt32` |

Без `kind` используется `uint32`; неизвестный `kind` также заменяется на `uint32`
с предупреждением. Если `message` отсутствует или не поддерживается записывающим модулем,
тип сообщения выбирается по `kind`. `message` не меняет декодирование памяти.

## Маски и границы

При наличии `mask` и `shift` сначала вычисляется `(слово & mask) >>> shift`,
затем применяется `kind`. Например, `kind: "uint32"`, `mask: 240`, `shift: 4`
выделяют биты 4–7 слова. Адрес остаётся адресом выровненного 32-битного слова.

`min` и `max` проверяются после декодирования. Значения за границами отмечаются
и не добавляются в ряд графика. Это фильтр допустимости, а не масштабирование:
перевода милливольт в вольты или иной формулы преобразования в формате нет.

## Проверки и ограничения

- Элемент, который не является объектом, пропускается с предупреждением.
- Поля без непустого `topic` или распознаваемого адреса пропускаются с предупреждением.
- Повторное имя `topic` пропускается; разные топики могут ссылаться на один адрес.
- Неизвестные дополнительные ключи игнорируются.
- Невыровненные адреса не опрашиваются. Каждый сигнал читается из 32-битного слова.
- Для известной карты выход за размеры Flash/SRAM сопровождается предупреждением.
  Для общего Cortex-M наличие памяти и её границы считаются неподтверждёнными.
- Чтение регистров периферии может иметь побочные эффекты; для обычной телеметрии
  используйте переменные в RAM. Предупреждение о карте не доказывает безопасность адреса.

Файл описывает местоположение значений, но не размещает переменные в памяти.
После пересборки получите адреса заново из соответствующего ELF или карты компоновщика.
Последний открытый файл запоминается приложением.
